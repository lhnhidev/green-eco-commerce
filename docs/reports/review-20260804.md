### [Critical] Checkout không lưu Order/Payment/OrderItems xuống DB — thiếu `SaveChangesAsync`
File: `apps/backend/src/GreenEcoCommerce.Application/Features/Checkout/Commands/CheckoutCommand.cs:137-164`
Mô tả: `dbContext.Orders.AddAsync(new Order {...})` chỉ thêm entity vào change tracker, không có `SaveChangesAsync` nào được gọi trước `transaction.CommitAsync(ct)`. Trong khi đó stock đã bị trừ (`ExecuteUpdateAsync`), ví đã bị trừ/cộng điểm (`SaveChangesAsync` nội bộ trong `WithdrawalWalletAsync`/`DepositWalletAsync`), coupon `UsedCount` đã tăng, giỏ hàng đã bị xóa (`Carts.ClearAsync`) — nhưng Order/Payment/OrderItems **không bao giờ được ghi vào DB**. API vẫn trả `200 OK` với `OrderId` không tồn tại thật trong DB.
Đề xuất fix: thêm `await dbContext.SaveChangesAsync(ct);` ngay sau khi build `Order`, trước `transaction.CommitAsync(ct)`.
Trạng thái: **Đã fix**

## Phần D — Ngoài phạm vi / Cần thảo luận thêm / Cần approval

Các mục dưới đây **KHÔNG được fix** trong đợt này vì lý do cụ thể — liệt kê để chủ dự án quyết định hướng tiếp theo.

1. **`UpdateOrderStatusCommand`/`UpdatePaymentStatusCommand` thiếu state machine** — cần team quyết định rule chuyển trạng thái hợp lệ (VD: Delivered/Cancelled là trạng thái cuối, không cho chuyển tiếp) trước khi code guard cứng, tránh đoán sai business rule làm hỏng luồng admin thao tác thủ công hợp lệ hiện tại.
2. **`GetAllReviewsQuery` thiếu phân trang server** — fix đúng cách sẽ đổi return type từ `ReviewDto[]` sang `PagedResult<ReviewDto>`, là breaking change cho `ReviewList.tsx` (đang phân trang client-side) và có thể cả OpenAPI client (Orval) — cần thảo luận scope trước khi đổi contract.
3. **Payment gateway giả lập (mục 9)** — cần tích hợp cổng thanh toán thật (VNPay/MoMo API) + webhook xác minh, vượt xa phạm vi "fix bug", đã có note sẵn trên diagram, chỉ trích dẫn lại.
4. **RAG dùng in-memory cosine similarity thay vì pgvector native (mục 12)** — fix đúng cách cần thêm vector index (HNSW/IVFFlat) + migration + viết lại query dùng `Pgvector.EFCore` (`CosineDistance`), là thay đổi hạ tầng persistence có rủi ro, cần approval trước khi migration.
5. **Dashboard 3 widget con không lọc theo tháng/năm (mục 10)** — cần sửa 3 handler backend (`RecentOrders`/`LowStockProducts`/`BestSellingProducts`) để nhận thêm tham số + 3 component frontend truyền tham số xuống; phạm vi vừa (không phải 1-dòng fix), nên tách thành task riêng thay vì gộp vào đợt fix bug này.
6. **Banner không có lịch hiển thị (mục 13)** — là tính năng mới (cần thêm cột `StartDate`/`EndDate` vào entity `Banner` + migration + UI mới), không phải bug, cần approval product trước khi thêm field vào CDM.
7. **Admin bị khóa hoàn toàn khỏi mọi route client kể cả trang tĩnh** (phát hiện mới, `RootLayout.tsx:24-26`) — có thể là chủ đích thiết kế (tách biệt console admin/storefront); chỉ ghi nhận, không tự ý đổi vì chưa rõ ý định sản phẩm.
8. **Inconsistent Redux state type sourcing** (phát hiện mới, cosmetic) — chỉ 1/6 slice import type từ `@types` module, còn lại khai inline; không phải bug, chỉ ghi nhận để team quyết định convention.

## Phần F — Đề xuất hướng giải quyết cho từng mục ở Phần D

### 1. State machine cho Order/Payment status (mục 5)
**Hướng đề xuất:** định nghĩa bảng chuyển trạng thái hợp lệ trước khi code — ví dụ `Pending → Confirmed → Shipping → Delivered` (Delivered là terminal), và `Pending → Cancelled` (terminal). Implement bằng 1 dictionary/switch kiểm tra `(current, target)` hợp lệ ngay trong `UpdateOrderStatusCommand`/`UpdatePaymentStatusCommand`, ném `BadRequestException` nếu sai — không cần state machine phức tạp, chỉ cần 1 hàm validate nhỏ.
**Cần trước khi làm:** team xác nhận bảng chuyển trạng thái (đặc biệt: có cho phép admin "sửa nhầm" quay lại Pending không, hay bắt buộc chỉ tiến).

### 2. Phân trang server cho Reviews (mục 7)
**Hướng đề xuất:** đổi `GetAllReviewsQuery` trả về `PagedResult<ReviewDto>` (dùng lại pattern `QueryParameters<TEntity>` đã có ở Users/Orders), thêm `Skip/Take`. Song song sửa `ReviewList.tsx` từ phân trang client-side sang gọi kèm `page`/`pageSize`, regenerate Orval client.
**Vì sao tách riêng:** đổi contract API là breaking change, không nên gộp vào đợt fix bug — làm PR riêng, báo trước cho FE dev nếu có ai khác đang đụng `ReviewList.tsx`.

### 3. Payment gateway giả lập (mục 9)
**Ngắn hạn (cho báo cáo niên luận):** giữ mô phỏng nhưng ghi rõ hơn trên UI ("Môi trường demo, chưa phải cổng thanh toán thật") để tránh hiểu lầm khi trình bày hội đồng.
**Dài hạn (nếu muốn production-ready):** tích hợp sandbox VNPay/MoMo (miễn phí cho dự án sinh viên) — BE tạo payment URL ký HMAC, redirect qua cổng, cổng gọi webhook/IPN về BE để cập nhật `Payment.Status` thật, verify chữ ký thay vì tự set `Paid` ngay lập tức.
**Lưu ý:** đây là feature lớn (vài ngày công), cần approval vì thêm secret/config mới và đụng luồng tiền (dù sandbox).

### 4. RAG dùng in-memory cosine similarity (mục 12)
**Hướng đề xuất 2 bước:**
1. Thêm HNSW/IVFFlat index lên cột embedding qua migration (`CREATE INDEX ... USING hnsw (embedding vector_cosine_ops)`).
2. Viết lại `BuildKnowledgeBaseBlockAsync` dùng `Pgvector.EFCore`'s `.OrderBy(e => e.Embedding.CosineDistance(queryEmbedding)).Take(N)` thay vì tải hết bảng về tính ở C#.
**Rủi ro:** nên benchmark vài query mẫu trước/sau trên nhánh riêng để đảm bảo kết quả ranking không lệch trước khi merge.

### 5. Dashboard 3 widget không lọc theo tháng/năm (mục 10)
**Hướng đề xuất:** thêm param `month`/`year` optional vào 3 query hiện có, filter theo `Order.CreatedAt`; FE truyền state tháng/năm đã chọn (đã có sẵn cho 4 StatCard) xuống 3 widget qua props.
**Cần quyết định trước:** `BestSellingProducts` hiện là "toàn thời gian" — đổi thành "trong tháng đã chọn" hay giữ nguyên + thêm toggle riêng? Nên hỏi ý nghĩa muốn thể hiện trước khi code vì ảnh hưởng cách demo.

### 6. Banner không có lịch hiển thị (mục 13)
**Hướng đề xuất:** thêm `StartDate`/`EndDate` (nullable) vào `Banner` entity + migration + cập nhật CDM, sửa `GetActiveBannersQuery` filter thêm điều kiện thời gian kết hợp `IsActive`, FE thêm 2 DateTimePicker vào `BannerForm`.
**Lưu ý:** đây là tính năng mới chứ không phải bug — chỉ nên làm nếu team thấy cần cho demo/thực tế, không bắt buộc.

### 7. Admin bị khóa khỏi route client tĩnh
**Hướng đề xuất:** làm rõ chủ đích trước. Nếu chủ đích tách biệt hoàn toàn admin console/storefront → giữ nguyên, chỉ thêm comment giải thích trong code để tránh future dev tưởng nhầm là bug. Nếu không chủ đích → chỉ redirect khi admin cố vào trang có giao dịch thật (cart/checkout/payment), còn trang tĩnh (about/contact/faq/terms/privacy/shipping/returns) thì cho xem bình thường.

### 8. Redux state type không nhất quán (cosmetic)
**Hướng đề xuất:** chọn 1 convention — khuyến nghị inline type ngay trong slice file (5/6 slice đã theo cách này), gộp luôn `AuthState` từ `authState.types.ts` vào `auth.slice.ts` cho đồng bộ. Việc nhỏ, làm nhanh trong 1 PR dọn dẹp riêng, không gấp.
